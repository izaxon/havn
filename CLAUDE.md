# Havn

Catan-style island colonisation game (Swedish/English UI): hot-seat play with AI
opponents, plus two-player online matches over WebRTC. `src/routes/api/rtc.ts` is
the signaling endpoint; rooms live in the database.

## Origin and ownership

- Built in the Grok App Builder and exported here ("Export from Grok" commits on
  `main`). `AGENTS.md` is Grok's sandbox contract and describes a Linux container
  at `/workspace` on port 8080. Ignore that plumbing on this machine, but keep
  the file, `startup.sh`, `public/__grok/`, `server/` and `scripts/grok-pwa-*`
  intact so the next export still works. Commit local work before pulling an
  export so the two merge instead of one overwriting the other.
- Auth is OFF (`VITE_AUTH_ENABLED` in `.grok/app-env.json`). Database is ON:
  Postgres via `DATABASE_URL` on Vercel, with a PGLite fallback locally that
  migrates itself. Never create a `.env` file.

## Running on Windows

- Always use the npm scripts (`npm run dev`, `npm run build`), never `vite`
  directly. They go through `scripts/with-app-env.mjs`, which on Windows
  resolves bare package commands to the package's JS entry (the `.cmd` shims
  cannot be spawned without a shell). The dev server listens on `0.0.0.0:8080`.
- `npm run build` ends with a migration step that is skipped without
  `DATABASE_URL`. That is expected locally.

## Gotchas

- `src/game/game.tsx` is a 3,800-line module recovered from the deployed bundle.
  It is `@ts-nocheck` and uses raw `jsx()` calls, so typecheck does not cover
  it. Verify game changes in the browser, and put new logic in separate modules
  (`src/game/*.ts`) rather than growing that file.
- `npm test` has known failures on a stock Windows machine: two symlink tests
  (need Developer Mode), three WebMCP tests (need `npx playwright install
  chromium`), and eight share-card injector tests in
  `scripts/grok-pwa-plugin.test.mjs` whose fixtures no longer match the repo's
  `src/lib/og/site.json`. Everything else passes.
- `.vercel/` and `screenshots/` are build and QA output and are gitignored;
  Vercel builds from source. `src/routeTree.gen.ts` is generated by the router
  plugin but stays tracked because the router imports it; it is pinned to LF
  so a build leaves no line-ending diff.
